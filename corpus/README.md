# 語料庫

L2 評測的題目。一份 `.json` 是一題：**素材 + 指令 + 標註**，格式見
`src/app/benchmark/case.py`，計分見 `metrics.score`。

目標是 50–100 支、維度鋪開（見 `docs/roadmap.md` §11）。現在有三支，
**而且三支都還是草稿**。

## 素材根目錄

標註裡的路徑一律是**相對於語料根目錄**的，不是絕對路徑，也不是 asset ID——
asset ID 每個工作區各自產生，拿它當錨點的語料換一台機器就什麼都量不到。

這批的根目錄是 `D:\video_work\`，底下是 `raw/<日期>/` 與 `music/`。
計分時由呼叫端把相對路徑接上根目錄、匯入成 asset，再把
`{相對路徑: asset_id}` 交給 `score`。

## ⚠️ 成片跟素材放在同一個資料夾

`raw/<日期>/` 底下每個 `<日期>.mp4`（`0828.mp4`、`0902.mp4`…）**是成片，不是素材**。
它們都是 30fps、都匯入過、都不在任何語意時間軸裡。

所以 `footage` 千萬不要用「列資料夾」的方式組——那等於把答案交給被測的那一端。
現有這三支是從語意時間軸的素材清單加上成片實際用到的配樂與旁白組出來的。

**成品本來就不該放在這裡。** `render_project` 會寫到 `workspace/outputs/<job_id>/`，
而且現在是用專案名稱命名的，找得到。素材根目錄保持只有素材，這個陷阱就結構性地消失了，
不必靠每次記得避開。

## 這三支還要做什麼

**`annotated_by` 是 `draft`，所以它們現在一分都算不出來**——`score` 會把
「標註還沒人審過」寫進 `Scorecard.unmeasured`，而只要 `unmeasured` 有東西就不算 `clean`。
這是故意的，要做的事是：

1. **把 `must_keep` 砍到只剩真的非留不可的。** 草稿是把成片用過的每一段都標成必留，
   而 must_keep 的總長幾乎等於目標長度——那不是底線，那是標準答案。
   照這樣算出來的分數量的是「跟舊的那一版有多像」，正好是 roadmap 說不要量的東西。
   一段一段看 `why`（裡面是當初選它的理由），把「選了」跟「非選不可」分開。
2. **補 `must_drop`。** 現在三支都是空的。舊的 plan 沒有留下 `rejected`，所以推不出來。
   `0902-closing` 的指令裡其實點名了一段不要用，但那段素材已經不在資料夾裡，
   所以連它也標不了。
3. **補 `cut_windows`。** 現在是空的。空的不算違規，計分器會當成「沒人畫過範圍」
   而不是「每個剪點都錯」。
4. **`taipei-internship` 與 `tainan-trip` 的 `instruction` 換成你當時真的講的話**，
   並把 `instruction_by` 改成 `user`。現在那兩句是反推的，而且是看過答案之後反推的。
   `0902-closing` 是你原本那份需求濃縮過的（`summarised`），要更準也可以自己再寫一次。
5. 改完把 `annotated_by` 改成 `user`，它才會開始算分。

`rubric` 是 L3 判官用的，這一層不計分，三支現在都是空的。
